# AirChoir

목소리에 화음을 더하는 **목소리 합창(Choir)**과, 마이크 없이 코드를 연주하는 **코드 악기(Chord)**를 갖춘 브라우저 앱입니다. 두 악기 모두 짧게 녹음한 소리를 오브로 만들어 반복 재생할 수 있습니다. 카메라 세션에서는 집중 연주 화면의 카메라·위젯·앱 소리를 영상으로 녹화하고 내려받을 수 있습니다. 기획과 다음 순서는 [PLAN.md](PLAN.md), 목소리 화음 엔진 비교 화면은 [phase0/](phase0/README.md)에 있습니다.

## 실행하기

```bash
cd apps/airchoir
python3 -m http.server 8000 --bind 127.0.0.1
# Chrome에서 http://localhost:8000 열기
```

앱 실행에는 패키지 설치가 필요하지 않습니다. 목소리 데모와 클릭·키보드 코드 연주는 마이크·카메라 권한이나 손 인식 모델 없이 동작합니다. 카메라를 사용하는 시작 버튼을 누르면 카메라 권한을 요청하고 MediaPipe 런타임·손 인식 모델을 외부에서 불러옵니다. 마이크로 노래할 때는 이어폰을 사용하세요.

## 악기와 시작 방법

| 악기 | 소리의 재료 | 선택 방식 |
|---|---|---|
| 목소리 합창 | 마이크·합성 목소리 데모·오디오 파일에 하모나이저 적용 | 한 손의 손가락 제스처 또는 합창 프리셋 휠 |
| 코드 악기 | 독립 Web Audio 합성기 | 한 휠에서 완성된 코드 선택 또는 두 휠에서 근음·코드 종류 선택 |

첫 화면은 기존 **목소리 합창·한 손·손동작** 설정입니다. `데모로 시작`을 누르면 실제 장치 대신 마우스 위치와 `0`~`5` 키로 손동작을 흉내 낼 수 있습니다. 합창에서 `클릭 · 키보드` 조작을 고르면 프리셋 휠이 나타납니다. 합창은 한 손만 지원하며 두 손 선택은 비활성화됩니다.

코드 악기로 바꾸면 **클릭 · 키보드**가 기본입니다. `코드 악기로 시작`은 마이크·데모 입력 없이 합성기만 준비합니다. 손으로 코드를 고르려면 시작 화면에서 `카메라로 코드 연주`를 선택하세요. 카메라 없이 시작한 코드 세션에서는 손동작으로 바꿀 수 없습니다. 세션을 종료한 뒤 카메라 버튼으로 다시 시작해야 합니다. 카메라 세션이 이미 준비돼 있으면 클릭·키보드와 손동작을 전환할 수 있습니다. 카메라나 모델 준비에 실패하면 클릭·키보드 조작으로 돌아갑니다.

목소리 합창의 시작 카드는 `데모로 바로 시작`(권한 없음) · `내 목소리로`(마이크 + 카메라) · `손동작 체험`(데모 노래 + 카메라) 세 가지이며, 카드마다 무엇이 필요한지 한 줄로 적혀 있습니다. 좁은 화면에서는 세션을 시작하기 전까지 이 안내가 맨 위에 옵니다. 악기 전환만으로 새 장치 권한을 요청하지 않습니다.

## 처음 안내

처음 세션을 시작하면 무대 왼쪽 아래에 다섯 단계 안내 카드가 나옵니다. 설명을 읽지 않아도 1분 안에 화음을 내고 첫 오브까지 만들어 보는 것이 목표입니다.

| 단계 | 넘어가는 조건 | 카메라 | 마우스 (데모) |
|---|---|---|---|
| 1. 소리 내기 | 입력 음이 0.6초 이어짐 | 이어폰을 끼고 "아~" | 데모 노래가 저절로 |
| 2. 화음 더하기 | 화음 1성부 이상이 0.8초 | 손가락 하나 | 무대 위에서 `1` |
| 3. 합창 키우기 | 화음 3성부 이상이 0.8초 | 손가락 3개 이상 | `3`·`4` |
| 4. 멈추기 | 주먹 0.3초 | 주먹 | `0` |
| 5. 첫 오브 | 오브 1개 | 핀치하고 한 마디 | `Space` 또는 녹음 시작 |

- 조건이 잠깐 이어져야 넘어가서 손 떨림이나 한 프레임 오인식으로 건너뛰지 않습니다. 카드의 얇은 막대가 유지 시간을 보여 줍니다. 한 프레임에 한 단계만 넘어갑니다.
- 목소리 합창을 손동작(또는 마우스)으로 지휘할 때만 진행합니다. 코드 악기·휠 선택·휠 설정 중에는 카드를 숨기고 시간도 세지 않습니다.
- `건너뛰기`로 한 단계씩 넘길 수 있고, `안내 끄기`를 누르면 다음 세션부터 저절로 열리지 않습니다. 끝까지 마쳐도 마찬가지입니다. 도움말의 `처음 안내 다시 보기`로 언제든 다시 시작합니다.
- 이 브라우저에 저장하는 값은 `airchoir.coach.v1`(`done`/`dismissed`) 하나뿐입니다. 저장이 막힌 환경에서도 안내는 동작합니다.
- 카드가 보이는 동안 오브는 카드 위쪽에만 놓입니다. 마우스 모드에서 카드 위를 누르면 녹음(핀치)으로 전달되지 않습니다. 집중 연주 화면에서도 같은 자리에 나옵니다.

## 집중 연주와 영상 녹화

카메라 준비가 끝나면 **집중 연주** 화면으로 들어갑니다. 카메라 없이 시작한 세션도 상단 `집중 연주` 버튼으로 큰 무대를 열 수 있지만 영상 녹화에는 준비된 카메라가 필요합니다. 집중 화면에는 설정·모든 소리 정지·작업 화면 복귀·영상 녹화·전체 화면 버튼이 남습니다. 브라우저 전체 화면은 선택 기능이며 자동으로 켜지지 않습니다.

영상은 **`녹화 시작`(또는 `R` 키)을 눌러야** 만들어집니다. 녹화 중에는 상단에 깜빡이는 `● 녹화 중 00:00` 표시와 무대 둘레의 붉은 테두리가 보입니다(테두리는 화면 표시일 뿐 영상에는 들어가지 않습니다). 카메라와 무대 위 현재 위젯에 **앱 전체 출력(기존 루프·메트로놈 포함)**을 합칩니다. 이미 준비된 오디오를 사용하므로 녹화 버튼이 마이크 권한을 다시 요청하지 않습니다. 서버 전송이나 자동 다운로드는 없습니다.

`녹화 정지` 후 마지막 영상 조각을 기다린 뒤 형식·길이·크기와 미리보기를 표시합니다. `영상 다운로드`로 저장하고, 새로 녹화하려면 `영상 버리기`로 현재 결과를 비워야 합니다. 다운로드만으로 결과가 삭제되지는 않습니다. 미리보기를 재생하면 현재 연주 소리는 정지합니다.

작업 화면 복귀, 설정·모드 변경, 창 초점 이탈, 페이지 숨김, 카메라 입력 종료, 세션 종료는 녹화를 마무리하고 결과를 **현재 페이지 메모리**에 유지합니다. 손 인식만 끊기면 현재 악기는 정지하지만 영상 녹화는 계속됩니다. `모든 소리 정지`도 연주·미리보기 소리를 정지하며 영상 녹화는 계속됩니다. **새로고침하거나 페이지를 닫으면 저장하지 않은 영상이 사라집니다.** 페이지 이탈 경고가 복원을 보장하지 않습니다.

녹화는 최대 10분·128MiB이며, 30fps를 요청하고 시작 시 무대 비율에 맞춰 긴 변 1280px·총 921,600px 이내로 정합니다. 브라우저가 지원하는 실제 형식에 따라 WebM 또는 MP4를 표시합니다. 자세한 정지 규칙·파일 제한·검증 범위는 [집중 연주와 영상 녹화](../../docs/AIRCHOIR_FOCUS_RECORDING.md)에 있습니다.

## 원형 휠 연주

- **코드 · 한 손**: C, Dm 같은 완성된 코드를 하나 고릅니다.
- **코드 · 두 손**: 첫 휠에서 근음, 두 번째 휠에서 코드 종류를 고릅니다. 클릭·키보드에서는 두 선택을 순서대로 누르면 조합이 유지되며, 둘 다 고른 뒤 소리가 납니다. 마우스를 올려놓는 것만으로는 연주되지 않습니다.
- **합창 · 한 손**: 설정한 합창 프리셋 중 하나를 고릅니다. 원래 입력 목소리의 음정과 합창 키·스케일을 사용합니다.
- 휠 항목과 중앙 **OFF**는 키보드로 초점을 옮겨 실행할 수 있는 버튼입니다. 선택한 항목은 색과 눌림 상태로 표시됩니다.
- 코드의 근음 선택은 합창의 기준 키(`tonic`)를 바꾸지 않습니다. 합창 키·스케일·엔진·입력 모니터는 코드 악기에서 비활성화되며, 합창으로 돌아오면 기존 설정을 사용합니다.

### 카메라 코드 선택

손바닥이 같은 구역에 **150ms** 머물면 선택을 확정합니다. 두 손 모드에서는 근음·종류 쌍을 함께 확정합니다. 중앙 OFF, 휠 밖, 손 누락은 현재 선택을 해제합니다. 경계의 짧은 흔들림 동안에는 이전의 유효한 선택을 유지합니다.

두 손의 역할은 **두 휠 중심을 잇는 방향축**을 기준으로 시작합니다. 첫째 휠(가로 배치의 왼쪽, 세로 배치의 위쪽)은 근음, 둘째 휠은 코드 종류이며 이전 프레임과의 위치 연속성을 따라 역할을 유지합니다. 현재 앱 입력은 카메라 영상을 거울·화면 비율에 맞게 변환한 좌표이며, 해부학적 왼손·오른손을 확정하는 방식이 아닙니다. 손이 교차하거나 너무 가까워져 역할이 모호하면 정지합니다. 양손을 모두 내렸다 다시 올려 역할을 다시 정할 수 있습니다.

휠 컨트롤러는 관측이 250ms 넘게 끊기면 선택을 폐기하고, 앱은 카메라 콜백이 **300ms** 넘게 없을 때 발음 중인 소리를 정지하는 별도 감시를 둡니다. 이 시간값은 선택·정리 정책이며 실제 카메라 인식 정확도나 음향 지연을 보장하지 않습니다.

## 연주 설정 (휠 · 손동작 감도)

`설정`을 누르면 **연주 휠**과 **손동작 감도** 두 탭이 있는 설정 창이 열립니다. 제목·탭·`취소`/`적용`은 늘 보이고 내용만 스크롤되어, 휴대폰에서도 적용 버튼을 찾으러 내려갈 필요가 없습니다.

**손동작 감도**는 `안정적으로` · `보통`(기본) · `빠르게` 중에서 고릅니다. 손가락 개수·핀치·휠 선택을 얼마나 빨리, 얼마나 단단히 판정할지를 함께 바꿉니다. 실제 손 사진 랜드마크에 MediaPipe 같은 잡음을 섞어 12·30·60fps 로 재생한 측정(`test/gesture-sensitivity.test.mjs`)에서, `보통`은 예전과 같은 반응 속도를 유지하면서, 펴짐/접힘 경계에 걸친 손가락 깜빡임을 12·30fps 에서 분당 12~18회 → 1회 안팎(60fps 는 2회 → 1회 미만)으로, 휠 OFF 경계 근처의 의도치 않은 소리 끊김을 30·60fps 에서 분당 11~21회 → 0회로 줄입니다. 손 높이(음량)는 프레임률과 무관하게 따라가 12fps 휴대폰에서도 반응이 약 5배 빨라졌습니다. 감도도 `적용`을 눌러야 바뀌고 `취소`하면 그대로입니다.

**연주 휠** 탭에서는 **한 손 코드 / 두 손 근음 / 두 손 코드 종류 / 합창 프리셋** 네 목록을 따로 편집합니다. 항목을 추가·삭제하거나 위/아래 버튼으로 순서를 바꾸면 원형 미리보기가 갱신됩니다. 각 목록은 1~12개여야 하고 중복은 허용하지 않습니다. 합창 프리셋은 제공되는 1~4 중에서만 고를 수 있어 실제 최대 4개입니다. 중앙 OFF는 목록과 별도로 항상 유지됩니다.

변경은 `적용`을 누를 때만 반영합니다. `취소`·닫기·설정창의 `Esc`는 편집 내용을 버립니다. `기본 목록 복원`도 편집 중인 초안만 바꾸므로 적용 전에는 저장되지 않습니다. 빈 목록 등 오류는 설정창에 표시됩니다.

목록·순서와 손동작 감도만 현재 브라우저의 `localStorage`에 저장합니다. 악기·입력 장치 선택, 발음 상태, 사진·카메라 영상·오디오·오브 녹음은 저장하지 않습니다. 저장이 불가능하면 이번 세션에 적용하고 안내를 표시합니다. 다른 기기나 브라우저와 동기화하지 않습니다.

## 정지와 세션 종료

아래 표의 녹음은 반복 재생용 **오브 오디오 녹음**입니다. 영상 파일은 위의 집중 연주 규칙에 따라 별도로 유지합니다.

| 조작 | 현재 악기 | 기존 루프·메트로놈 | 오브 녹음 버퍼 |
|---|---|---|---|
| 중앙 OFF · 수동 조작 중 휠 영역 벗어나기 | 현재 화음/코드 선택 해제. 합창의 원래 입력 모니터는 유지 | 계속 재생 | 유지 |
| 모든 소리 정지 · 작업 화면에서 연주 중 `Esc` · 창 초점 이탈 · 페이지 숨김 | 출력 음소거, 자동 재발음 차단 | 루프 정지·음소거, 메트로놈 끄기, 진행 중 오브 녹음 취소 | 완성된 오브 유지 |
| 악기·손 수·조작 방식 변경 · 설정 열기/적용 | 전체 정지와 같은 정리 후 명시적 재선택 필요 | 정지 | 완성된 오브 유지 |
| 세션 종료 · 페이지 떠나기 | 입력·카메라·오디오 자원 정리 | 정지 | 삭제 |

전체 정지 후에는 휠을 다시 선택하거나 손을 내렸다 올려 연주를 재개합니다. 보관된 오브는 목록에서 음소거를 풀어 다시 재생할 수 있습니다. 설정을 취소해도 정지된 소리를 자동으로 재개하지 않습니다. 오브 녹음 옆의 **취소** 버튼은 현재 오브 녹음만 취소합니다.

`Esc`는 **집중 화면에서는 녹화를 마무리하고 작업 화면으로 복귀**합니다. 세션은 종료하지 않습니다. 설정창이 열려 있으면 설정만 취소합니다. 일반 작업 화면에서는 전체 소리 정지이며, 입력란·선택 상자에서는 해당 컨트롤의 키 동작을 우선합니다. 시작 준비 중에는 시작을 취소합니다. 브라우저 전체 화면의 `Esc`는 브라우저가 먼저 처리할 수 있습니다.

## 목소리 합창의 손동작

아래는 기본 프리셋 순서입니다. 휠 설정에서 합창 목록의 순서를 바꾸면 손가락 수가 그 순서의 프리셋에 대응합니다. 목록보다 많은 손가락은 마지막 프리셋을 사용합니다.

| 손동작 | 기본 효과 |
|---|---|
| 손이 안 보임 | 화음 없음, 입력 목소리만 |
| 손가락 1개 | 3도 위 |
| 손가락 2개 | 3도 + 5도 위 |
| 손가락 3개 | 3·5도 + 옥타브 아래 베이스 |
| 손가락 4~5개 | 풀 합창 |
| 주먹 | 합창 화음 정지 |
| 손 높이 | 합창단 음량 |
| 손 좌우 | 왼쪽은 어둡고 울림 많게, 오른쪽은 밝고 선명하게 |

기존 합창 제스처는 손이 둘이면 크게 보이는 손을 사용합니다. 손가락 개수는 90ms 유지 후 바뀌고 짧은 손 누락에는 250ms 유예가 있습니다. 이 정책은 위의 코드 휠 판정과 별개입니다. 엔진은 기본 PSOLA이며 `Q`·`W`·`E`로 그레인·PSOLA·합성을 바꿀 수 있습니다.

합창 음색: 성부마다 음정이 천천히 조금씩(±6 cent) 다르게 흔들리고 4~14ms 씩 늦게 들어와 한 목소리를 복사한 기계음 대신 여러 사람이 부르는 소리에 가깝게 들립니다. 성부 수가 늘어도 합창단 전체 크기는 비슷하게 맞추고(풀 합창이 1성부의 약 1.3배), 음높이를 옮긴 목소리의 거친 고역을 살짝 다듬습니다. 합성 엔진은 성부마다 두 사람이 함께 부르는 '아~'(가수 포먼트, 높은 음의 첫 포먼트 맞춤, 숨소리)입니다. 출력 끝에는 리미터가 있어 성부·오브·코드가 겹쳐도 스피커와 녹화가 찌그러지지 않습니다. 코드 악기는 삼각파 대신 따뜻한 패드 파형이며 화음 음마다 몇 cent 씩 달라 천천히 맥놀이합니다.

## 오브: 반복 녹음

`녹음 시작` → `녹음 마치기` 또는 `Space`로 다음 마디부터 녹음하고 마디 끝에 완성합니다. 최대 4마디, 오브 6개입니다. 합창 손동작에서는 핀치를 유지해 같은 녹음을 시작하고 놓아 마칠 수도 있습니다. 완성된 오브를 던지거나 내려놓으면 위치에 따라 패닝과 음량이 정해집니다. 목록에서 선택·내려놓기·음소거·삭제할 수 있습니다.

녹음에는 **선택한 악기 하나**만 들어갑니다. 합창은 입력 목소리와 합창 화음, 코드 악기는 독립 합성기의 반주를 담습니다. 이미 재생 중인 오브와 메트로놈은 녹음 버스에서 제외합니다. 악기 전환은 진행 중 녹음을 취소해 두 경로가 한 녹음에 섞이지 않게 합니다.

마이크 합창 녹음에는 입력·출력 지연 추정만큼 캡처 시점을 보정합니다. 코드 악기는 이 **마이크 보정값을 0**으로 사용합니다. 실제 합성기나 출력 장치의 지연이 0이라는 의미는 아닙니다.

메트로놈은 녹음 대기·녹음 중 자동으로 켜집니다. 70~130 BPM을 제공하며 녹음 중이거나 오브가 남아 있으면 BPM이 잠깁니다. `모두 지우기`는 녹음과 오브를 지우고 미완료 캡처 요청도 취소합니다. 오브는 현재 세션의 메모리에만 있으며 세션 종료·새로고침 후 복원되지 않습니다.

## 테스트

```bash
cd apps/airchoir
npm test                       # Node 22+: 오프라인 단위 테스트, 패키지 설치 불필요
npm ci --ignore-scripts         # 브라우저 검증용 개발 의존성 설치가 필요한 경우만
npm run check                  # 기존 포인터·Phase 0·컨트롤·처음 안내 검증
npm run check:performance       # 악기·휠·설정·정지·코드 녹음 검증
npm run check:focus             # 가상 카메라·실제 영상 파일·집중 화면 검증
# Chrome이 이미 설치되어 있다면:
BROWSER_CHANNEL=chrome npm run check
BROWSER_CHANNEL=chrome npm run check:performance
BROWSER_CHANNEL=chrome npm run check:focus
```

브라우저 검사 명령은 브라우저를 설치하지 않습니다. 이미 받아 둔 Chromium 실행 파일은 `BROWSER_PATH=/절대/경로/chromium`으로 지정할 수 있습니다. 기존 Playwright는 `PLAYWRIGHT_MODULE=/절대/경로/playwright/index.mjs`로 재사용할 수 있습니다. `check:focus`는 기존 `ffmpeg`·`ffprobe`가 `PATH`에 있어야 하며, `SHOTS=/절대/결과/폴더`를 주면 영상·스크린샷·JSON 결과를 남깁니다.

- 단위 테스트는 DSP·녹음·오브, 합성기 정리, 코드 목록 검증·저장 실패, 원형 판정·손 순서·손 누락과 초기화 경쟁 상태를 확인합니다.
- `pointer.check.mjs`, `controls.check.mjs`는 실제 AudioWorklet 합성 데모와 UI 조작을 사용하고, `phase0.check.mjs`의 마이크 입력은 Chrome 가상 장치입니다. 실제 마이크·카메라 검증이 아닙니다.
- `coach.check.mjs`는 합성 데모와 마우스·숫자 키만으로 다섯 단계를 끝까지 진행하고(데스크톱·모바일 폭), 완료·끄기 저장, 다시 보기, 코드 악기·휠 입력 중 숨김, 카드 버튼이 녹음을 시작하지 않는지, 무대 안·HUD와 겹치지 않음·가로 넘침 없음·44px 버튼을 확인합니다. 다른 브라우저 검사는 무대를 비워 두려고 안내를 끈 상태로 시작합니다.
- `performance.check.mjs`는 실제 브라우저에서 수동 휠·설정 적용/취소/재열기·재시작, 정지 상태, 실제 코드 루프 캡처 등을 확인합니다. 장치 요청과 외부 네트워크를 차단합니다.
- `focus.check.mjs`는 Chrome 가상 카메라·저장된 손 좌표·합성 소리로 실제 MediaRecorder를 실행합니다. 카메라/위젯 픽셀·음성 트랙·파일 디코딩, 명시적 다운로드, 손 누락과 정지/복귀 경계, 미리보기 정지, 모바일 도구 모음을 확인합니다. 실제 장치·외부 모델·외부 네트워크는 사용하지 않습니다.
- `npm test`의 손동작 입력은 저장소의 랜드마크 또는 합성 좌표이므로 모델 다운로드가 없습니다.
- 선택적 **`npm run check:camera`**는 실제 손 사진을 가짜 카메라에 넣어 모델을 실행합니다. 처음에는 MediaPipe·모델·사진을 `test/.cache`로 다운로드하고 `ffmpeg`를 사용합니다. 기본 검사에 포함하지 않으며, 이번 변경에서 실행하지 않았습니다. GPU가 없는 환경에서는 주소에 `#cpu`를 붙여 CPU 인식을 선택할 수 있습니다.

## 검증 범위와 남은 확인

이번 확인은 합성 소리·합성 손 좌표와 데스크톱 Chrome의 실제 화면·오디오·MediaRecorder 처리 경로를 대상으로 합니다. 영상 회귀 검사는 가상 카메라의 WebM(VP9+Opus) 파일을 만들고 `ffprobe`·`ffmpeg`로 영상·소리를 확인했습니다. **실제 카메라와 새 손 인식 모델 실행, 실제 목소리의 음질, 마이크 박자 보정, Android 기기의 성능·음질, 모바일 Safari와 MP4 녹화는 미검증**입니다. 모바일 폭의 화면 검사는 실제 모바일 장치의 성능을 보장하지 않습니다. 자동 테스트 통과나 화면 지연 표시를 음질 개선 또는 장치 지연 측정 결과로 해석하지 않습니다.

## 다른 앱과의 분리

이 폴더의 JavaScript 환경은 `../band2sheet`의 Python 환경을 사용하지 않습니다. 별도 서버 데이터 폴더나 API 키가 필요하지 않습니다. 개발 의존성은 `node_modules/`, 선택적 카메라 검증 자료는 `test/.cache/`에 둡니다. band2sheet와 함께 실행할 때는 서버 포트를 다르게 지정하세요.
