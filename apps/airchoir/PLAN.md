# AirChoir 현재 구현과 검증 범위

목소리를 합창으로 만들거나 독립 코드 악기를 연주하고, 그 소리를 오브 루프로 쌓는 브라우저 앱입니다. 같은 저장소의 `apps/band2sheet`와 독립적으로 실행합니다. 현재 사용 방법과 검사 명령은 [README.md](README.md)에 있습니다.

## 현재 구현 범위

| 영역 | 구현 | 실제 검증의 경계 |
|---|---|---|
| Phase 0: 합창 엔진 비교 | 음정 검출, 그레인·PSOLA·합성 보이스 비교 화면 | 합성 입력 처리와 상태 확인. 실제 목소리 음질·장치 지연 평가는 남음 |
| Phase 1: 목소리 합창 | 마이크·데모·파일 입력, 한 손 지휘, 키·스케일·엔진 설정 | 기존 손동작 판정과 입력 수명 관리. 실제 장치 조합 평가는 남음 |
| Phase 2: 오브 | 마디 녹음, 최대 6개 루프, 선택·이동·음소거·삭제 | 합성 입력으로 실제 AudioWorklet 녹음 경로와 상태 확인 |
| 코드 악기와 원형 휠 | 독립 합성기, 한 손 코드/두 손 근음·종류, 합창 프리셋, 목록 편집 | 클릭·키보드 실제 브라우저 및 합성 손 좌표. 실제 카메라·Android 품질은 남음 |
| Phase 4 일부: 처음 안내 | 다섯 단계 카드(소리→화음→키우기→멈추기→첫 오브), 유지 조건, 건너뛰기·끄기·다시 보기 | 합성 데모·마우스로 끝까지 진행(약 10초). 실제 처음 쓰는 사람의 1분 기준 평가는 남음 |
| 집중 연주와 영상 녹화 | 큰 카메라·현재 위젯, 작업 화면 복귀, 명시적 녹화·미리보기·다운로드 | Chrome 가상 카메라와 합성 소리, 실제 MediaRecorder와 파일 디코딩. 실제 장치·모바일 코덱은 남음 |

구현 완료와 실제 음악 품질 검증 완료는 구분합니다. 합주·자동 키 감지는 현재 기능이 아닙니다. 처음 안내는 [README](README.md#처음-안내)에 있습니다. 집중 화면과 로컬 영상 녹화의 세부 정책은 [구현 문서](../../docs/AIRCHOIR_FOCUS_RECORDING.md)에 있습니다.

## 악기와 입력 정책

앱은 한 번에 하나의 악기를 선택합니다.

- **Choir**: 원래 입력 목소리와 하모나이저를 사용합니다. 한 손만 지원합니다. 기존 손가락 지휘 또는 원형 프리셋 버튼으로 합창 구성을 고릅니다.
- **Chord**: 마이크와 음정 추정 없이 Web Audio 합성기로 코드 음을 만듭니다. 한 휠의 항목은 완성된 `{root, quality}` 코드입니다. 두 휠은 근음과 종류를 각각 고르며 두 선택이 모두 유효할 때 발음합니다.
- 악기와 별도로 입력 소유자를 손동작/클릭·키보드 중에서 정합니다. 동시에 두 입력이 소리를 덮어쓰지 않습니다. 코드 악기 진입·권한 없는 시작은 클릭·키보드가 기본입니다.
- 초기 화면의 합창·한 손·손동작 설정은 기존 데모 흐름과 호환됩니다. 데모에서는 마우스 위치와 숫자 키로 손을 대신하며 장치 권한을 요청하지 않습니다.
- 카메라는 명시적인 카메라 시작 버튼에서 준비합니다. 카메라 없이 시작한 코드 세션의 손동작 선택은 비활성화하고 세션 종료 후 다시 시작하도록 안내합니다. 이미 카메라가 준비된 세션은 입력 방식을 전환할 수 있습니다.
- 코드 근음은 합창의 `tonic`을 변경하지 않습니다. 코드 악기에 쓰지 않는 합창 입력·키·스케일·엔진 조작은 비활성화합니다.

## 원형 휠과 손 추적

항목은 위에서 시작해 시계 방향으로 배치합니다. 중앙 OFF는 고정이며 목록 항목으로 제거할 수 없습니다. 클릭·키보드는 원형 위의 실제 버튼으로 선택하고 hover만으로 발음하지 않습니다. 수동 두 휠은 근음과 종류를 순서대로 선택해 조합을 유지합니다.

카메라 판정은 UI가 반환한 실제 휠 중심·반경과 화면 좌표를 사용합니다. 손바닥이 같은 구역에 **150ms** 유지되면 선택을 확정하고, 두 손의 근음·종류는 함께 확정합니다. 구역 경계의 짧은 흔들림에는 이전 유효 선택을 유지하되, 중앙 OFF·외곽·손 누락은 정지합니다. 컨트롤러는 250ms 넘은 오래된 관측을 폐기하고 앱에는 **300ms 카메라 콜백 중단 감시**를 둡니다.

두 손의 초기 역할은 두 휠 중심을 잇는 방향축으로 정합니다. 첫째 휠(가로 배치의 왼쪽, 세로 배치의 위쪽)은 근음, 둘째 휠은 코드 종류이며 이후 위치 연속성으로 역할을 유지합니다. 현재 앱이 공급하는 값은 거울·화면 비율을 반영한 좌표입니다. 손 크기나 결과 배열 순서, 확인되지 않은 해부학적 좌우 판정을 역할 기준으로 사용하지 않습니다. 교차·근접으로 역할이 모호해지면 OFF로 잠그고 양손이 모두 사라진 뒤 다시 정합니다. 한/두 손 전환·설정 변경은 이전 확정값을 폐기합니다.

기존 합창 손가락 판정(90ms 유지, 짧은 손 누락 250ms 유예)은 코드 휠 정책과 분리합니다. 합창 프리셋 목록 순서를 바꾸면 손가락 개수가 그 목록의 순서에 대응합니다.

## 설정과 저장

편집 가능한 네 목록은 완성 코드, 근음, 코드 종류, 합창 프리셋입니다. 공통 검증은 1~12개·중복 없음·허용된 값만 사용입니다. 합창 프리셋은 1~4만 제공하므로 최대 4개입니다.

설정창은 초안을 별도로 편집합니다. 추가·삭제·순서 변경은 원형 미리보기에만 즉시 반영하고 **적용 시점**에 연주 상태와 저장 목록을 교체합니다. 취소·닫기·설정창의 Escape는 초안을 버립니다. 기본 목록 복원도 적용을 거쳐야 저장됩니다. 빈 목록·중복·허용 범위 오류를 화면에서 설명합니다.

`localStorage`에는 버전이 있는 목록과 순서만 저장합니다. 현재 악기·장치·발음·이미지·영상·음성·루프는 저장하지 않습니다. 손상된 설정은 기본값으로 읽고 안내하며, 저장 실패는 이번 세션 적용과 기기 저장 실패를 구분해 알립니다.

## 정지와 수명 관리

- **중앙 OFF·수동 휠 이탈**: 현재 악기 선택과 화음/코드를 해제합니다. 합창의 dry 입력 모니터, 기존 루프와 메트로놈은 유지합니다.
- **모든 소리 정지·연주 Escape·창 blur·페이지 hidden**: 전체 출력을 음소거하고 루프 재생 노드를 정지합니다. 메트로놈을 끄고 진행 중 녹음을 취소합니다. 완성된 오브 버퍼는 보존합니다.
- **악기·손 수·입력 소유자 변경, 설정 열기/적용**: 같은 전체 정지를 수행하며 명시적 재선택 전에는 재발음하지 않습니다. 설정 취소가 이전 소리를 자동으로 다시 켜지는 않게 합니다.
- **세션 종료·페이지 떠나기**: 입력·카메라·오디오와 요청을 정리하고 오브 버퍼까지 삭제합니다.
- 녹음 옆 취소 버튼은 현재 녹음만 취소합니다. 입력란/선택 상자의 기본 키 동작은 전역 단축키보다 우선합니다. 설정창 Escape는 창 취소입니다.

취소·종료된 오디오/카메라/캡처 요청의 늦은 응답은 새 세션을 변경하지 않아야 합니다. 루프를 보관한 전체 정지와 삭제하는 세션 종료는 회귀검사에서 구분합니다.

집중 연주 화면의 Escape는 전체 소리를 멈추고 영상 녹화를 마무리한 뒤 작업 화면으로 돌아갑니다. 설정창에서는 먼저 설정창을 닫습니다. 전체 소리 정지는 미리보기 소리도 멈추지만 진행 중인 영상 녹화는 유지합니다. 설정·모드 변경, 창 이탈·페이지 숨김, 카메라 중단, 세션 종료는 영상을 마무리합니다. 손 인식 콜백만 끊긴 경우는 악기 소리를 멈추고 영상 녹화 상태를 별도로 표시합니다.

## 녹음과 오디오 경로

합창은 입력 목소리·하모나이저를, 코드 악기는 독립 반주 합성기를 선택된 녹음 버스에 연결합니다. 한 번의 녹음에는 한 악기만 들어갑니다. 기존 루프·메트로놈은 재녹음하지 않습니다. 악기 변경으로 진행 중 녹음을 먼저 취소합니다.

마이크 합창 캡처는 입출력 지연 추정값으로 시작 샘플을 보정합니다. 코드 악기의 **마이크 보정 오프셋은 0**입니다. 실제 출력 지연이나 합성기 반응 시간이 0이라는 뜻은 아닙니다. 합성기는 반복된 같은 코드로 발음 노드를 계속 늘리지 않으며, 코드 변경·정지·컨텍스트 정지·해제에서 잔여 노드를 정리합니다.

영상 녹화는 오브 녹음과 별개입니다. 카메라와 현재 위젯을 합성한 캔버스에 최종 오디오 출력(루프·메트로놈 포함)을 연결하며 마이크 트랙을 중복 추가하지 않습니다. 준비된 카메라 세션에서 버튼으로 시작하고 최대 10분·128MiB로 제한합니다. 지원되는 실제 MIME에 맞춰 WebM 또는 MP4로 내려받습니다. 완료 영상은 해당 페이지 메모리에 보관하며 다운로드·버리기는 명시적 조작입니다. 세션 종료 후에도 페이지가 유지되는 동안 결과는 남지만, 새로고침·페이지 종료 후 복원하지 않습니다.

## 화면과 접근성

상단에 악기·한/두 손·입력 선택, 휠 설정, 모든 소리 정지를 배치합니다. 무대는 기존 합창/오브 화면 또는 원형 휠을 보여주고, 녹음·BPM·루프 목록과 함께 사용합니다. 휠 항목은 키보드 버튼이며 설정 순서 변경도 드래그 없이 위/아래 버튼으로 가능합니다. 중앙 OFF와 전체 정지는 역할을 구분해 표시합니다. 모바일 폭에서는 두 휠을 세로로 배치하고 터치 영역을 최소 44px로 유지합니다.

## 검증과 다음 순서

- `npm test`: DSP·녹음·오브·장치 수명, 코드 데이터·저장, 합성기 노드 정리, 원형 좌표·손 역할·손 누락을 오프라인으로 검증합니다.
- `npm run check`: 기존 포인터·Phase 0·컨트롤의 실제 브라우저 회귀검사입니다.
- `npm run check:performance`: 장치·외부 요청을 차단하고 악기/한·두 휠/설정·저장/정지/실제 코드 루프 캡처를 검사합니다.
- `npm run check:focus`: Chrome 가상 카메라·합성 손 좌표로 집중 화면과 실제 영상 녹화·다운로드·중단·재녹화를 검사합니다. 설치된 ffmpeg·ffprobe로 영상/오디오 스트림과 합성 화면을 확인하며, 실제 장치·외부 모델은 사용하지 않습니다.
- `npm run check:camera`는 별도 선택 검사입니다. 모델·사진 다운로드와 가짜 카메라를 사용하며 기본 검사에 포함하지 않습니다.

이번 작업에서 **실제 카메라·모델 실행, 실제 목소리의 음질, 실제 마이크 박자 보정, Android 성능·음질, 모바일 Safari**는 확인하지 않았습니다. 화면 폭 검사나 합성 버퍼의 신호 확인으로 이를 대체하지 않습니다.

다음 순서는 실제 이어폰·목소리·카메라를 쓰는 평가 범위를 먼저 정하고, 한/두 손 선택 안정성·멈춤·장치 지연·음질을 기록하는 것입니다. 이후 초보자 안내와 모바일 기기 검증을 조율합니다.

아래는 기존 기획을 보존한 내용입니다. 후보 기술·미래 기능·완료 기준을 포함하며, 현재 구현 여부와 이번 검증 범위는 위 설명을 기준으로 합니다.

# 🎤 AirChoir (가칭: 허밍 합창단) 기획서

> **허밍 한 번이면, 내가 합창단.**
> 마이크에 노래하고 손을 움직이면 내 목소리가 화음이 되고, 그 소리를 손으로 잡아 던져서 루프로 쌓는 브라우저 앱.

이 폴더는 같은 레포의 `apps/band2sheet`(악보 앱)과는 **별개의 앱**입니다.

## 1. 한 줄 컨셉과 차별점

| 기존 오픈소스 (gesture-synth, SoundGo, WebChord 등) | AirChoir |
|---|---|
| 손으로 **코드를 골라서** 신스를 연주 | **내 목소리**가 재료. 손은 지휘봉 |
| 음악 이론을 알아야 재미있음 | 이론 없이 허밍만 해도 됨 |
| 혼자 연주하고 끝 | 소리를 **오브**로 잡아 던져 루프로 쌓기, **친구와 합주** |

- 타깃: 노래는 좋아하지만 악기는 못 다루는 사람, 영상으로 올려서 보여 주고 싶은 사람
- 플랫폼: **브라우저** (설치 없음, 링크 공유). 데스크톱 Chrome/Edge 우선, 모바일은 2차
- 이어폰 착용 필수 (스피커로 들으면 마이크에 되먹임이 생김)

## 2. 모드 구성

| 모드 | 이름 | 한 줄 설명 | 우선순위 |
|---|---|---|---|
| ① | **합창단 모드** | 노래하면 내 목소리로 화음 3~4성부를 쌓아 줌. 손으로 지휘 | MVP |
| ③ | **오브 모드** | 소리를 녹음해 공중에 뜬 구체로 만들고 던지면 루프로 재생 | MVP |
| ⑤ | **합주 모드** (별도) | 링크로 친구를 초대해 둘이 한 소리를 같이 만듦 | 2차 |

①과 ③은 한 화면에서 같이 동작합니다. (합창단 소리를 오브로 녹음 가능)
⑤는 **별도 진입 화면**을 가진 독립 모드로 둡니다.

## 3. 모드 ① 합창단 모드

### 동작 흐름
1. 키 선택(기본 C 장조) 또는 **자동 감지**(처음 5초 허밍으로 추정)
2. 마이크로 들어온 목소리의 음높이(pitch)를 실시간 검출 → 가장 가까운 스케일 음으로 해석
3. 손 제스처로 정한 **화음 구성**에 맞춰 목소리를 음정 이동시켜 쌓아 줌
4. 합쳐진 소리를 헤드폰으로 출력

### 제스처 (한 손으로 충분, 왼손 오른손 구분 없음)

| 제스처 | 효과 |
|---|---|
| 손 안 보임 | 화음 없음 (원래 목소리만) |
| 손가락 1개 | 3도 위 화음 |
| 손가락 2개 | 3도 위 + 5도 위 (3화음) |
| 손가락 3개 | 3도 위 + 5도 위 + 옥타브 아래 베이스 |
| 손가락 4~5개 | 풀 합창 (4성부 + 옥타브 더블링) |
| 손 높이 | 합창단 볼륨 (위로 갈수록 커짐) |
| 손바닥 좌우 | 화음 밝기 (왼쪽은 어둡게 / 오른쪽은 밝게: 필터와 리버브) |
| 주먹 쥐기 | 즉시 컷 (합창단 정지) |
| 손 쫙 펴며 위로 | 크레센도 |

- 도수는 **현재 키의 스케일 안에서 자동 계산**해서 불협화음이 나지 않게 함 (다이아토닉 하모니)
- 디버그용 화면에 "지금 인식된 음 / 만들어진 화음 음"을 표시

### 기술 선택
| 기능 | 선택 | 비고 |
|---|---|---|
| 손 추적 | MediaPipe Tasks Vision `HandLandmarker` | Apache-2.0, 브라우저 WASM |
| 음높이 검출 | AudioWorklet에서 McLeod/YIN 알고리즘 | 후보: `pitchy`. 라이선스 확인 필요 |
| 화음 생성 | **음정 이동(PitchShift)** 으로 내 목소리를 변조 | 1차: Tone.js `PitchShift` (MIT) |
| 대체 경로 | 검출한 음에 맞춰 "아~" 합성 보이스 재생 | 음정 이동 품질이 낮을 때의 안전장치 |
| 오디오 엔진 | Web Audio API (+ Tone.js) | |

**가장 큰 기술 리스크**: 실시간 음정 이동의 음질과 지연. Tone.js의 PitchShift는 그레인 방식이라 약간 울리고 지연이 생길 수 있음. Phase 0에서 먼저 검증하고, 기준에 못 미치면 위상 보코더나 PSOLA 계열 AudioWorklet을 직접 구현하거나 합성 보이스로 대체.

## 4. 모드 ③ 오브 모드

소리를 **눈에 보이는 물건**으로 만들어 다루는 모드입니다.

### 오브 만들기 → 던지기 → 쌓기
1. **핀치(엄지+검지 붙이기)를 유지**하면 녹음 시작 (4박 카운트인, 메트로놈 BPM은 설정)
2. 핀치를 놓으면 다음 마디 끝에서 녹음이 끝나고, **손 위에 오브가 생김** (오브 색 = 음정 높이, 크기 = 길이)
3. 손을 **휙 던지면** 화면 그 위치에 안착해서 **무한 루프**로 재생
4. 오브를 쌓아 올리면 루프 스테이션이 됨

### 오브 조작

| 조작 | 효과 |
|---|---|
| 던진 위치의 좌우 | 패닝 |
| 던진 위치의 높이 | 볼륨 |
| 오브를 핀치로 다시 잡기 | 위치 이동 |
| 오브를 쥐어 터뜨리기 (주먹) | 삭제 |
| 오브 위에 손을 대고 펼치기 | 뮤트 토글 |

- 오브는 최대 6개 (CPU 보호)
- 모든 오브는 BPM 그리드에 맞춰 시작해서 박이 어긋나지 않음
- 오브는 숨 쉬듯 박자에 맞춰 커졌다 작아졌다 함 (시각 피드백)
- 합창단 모드의 소리를 그대로 녹음할 수 있어서 **합창 위에 합창을 쌓기** 가능

### 기술
- 녹음: `AudioWorklet` 링 버퍼로 마디 단위 캡처 → `AudioBufferSourceNode` 루프 재생
- 오브 물리: Canvas 2D + 단순 속도/감쇠 (던진 속도는 손목 랜드마크의 프레임 간 이동량으로 계산)
- 핀치/주먹/손 펼침 판정: 랜드마크 거리 기반 + 3프레임 이상 유지해야 인정(떨림 방지)

## 5. 모드 ⑤ 합주 모드 (별도 모드)

링크 하나로 친구를 초대해서 **한 소리를 같이 만드는** 모드입니다.

### 설계 핵심: 소리 대신 "제스처 신호"를 주고받기
인터넷 지연(100ms 이상) 때문에 두 사람의 소리를 박자에 맞게 섞는 건 불가능합니다. 그래서 **오디오는 한 사람의 컴퓨터에서만 만들고, 상대방은 제스처 신호(작은 데이터)만 보내는** 구조를 씁니다. 제스처는 지연에 둔감해서 괜찮습니다.

```
 [가수]   마이크 → 합창단 엔진 ──→ 소리 출력 + 소리/영상 스트림을 상대에게 전송
              ▲
              │ (제스처 이벤트, 수십 바이트, DataChannel)
 [지휘자] 손 추적 ──┘      가수가 만든 소리를 스트림으로 듣고 지휘
```

### 역할 분담 방식 (합주 모드 안의 선택지)

| 방식 | 가수 | 지휘자 | 재미 포인트 |
|---|---|---|---|
| **가수 + 지휘자** | 노래만 함 | 손으로 화음과 볼륨 조작 | 한 사람은 노래만, 한 사람은 지휘만 |
| **왼손 + 오른손** | 노래 (가수 본인도 손 사용) | 가수가 화음 구성을, 상대가 볼륨/컷을 담당 | 호흡이 안 맞으면 소리가 안 남 |
| **오브 공동 작업** | 소리 만들기 | 만들어진 오브를 던질 위치를 상대가 결정 | 서로의 손으로 오브를 주고받기 |

- 화면: 두 사람의 카메라 영상을 **한 화면에 합성**하고, 손 스켈레톤과 오브를 그 위에 그림
- 방 만들기: 6자리 코드 또는 링크 (`/room/abc123`)
- 인원: 2명으로 시작 (관전자 추가는 나중에)

### 기술
- 연결: WebRTC (영상/음성 스트림 + DataChannel)
- 시그널링(연결 중개): 1차 PeerJS 공용 브로커로 시작, 안정화하면 PartyKit이나 직접 만든 소형 WebSocket 서버로 교체
- 한 방의 상태(키, BPM, 오브 목록)는 **가수 쪽이 원본**을 가지고 상대에게 반영

## 10. 아직 정해야 할 것

1. 이름: AirChoir / 허밍 합창단 / 다른 이름?
2. 기본 화음 방식: 이론적으로 맞는 **다이아토닉 3·5도**로 시작할지, 재즈 느낌의 **보이싱**까지 지원할지
3. 합주 모드의 첫 번째 방식: **가수 + 지휘자**를 추천 (가장 구현이 단순하고 재미가 분명함)
4. 영상 녹화(릴스용) 버튼은 이번 범위에서 뺐음. 필요하면 Phase 4에서 `MediaRecorder`로 추가 가능

## 현재 개발 확인과 다음 순서

- `apps/airchoir` 안에서 독립 실행·테스트합니다. 오프라인 검증과 모델을 받는 카메라 검증은 [README](README.md#테스트)에서 분리했습니다.
- Phase 2 안정화: 초기화 실패 후 재시도, 취소된 녹음/카메라 요청의 늦은 응답 차단, 오브 삭제와 페이지 종료 시 자원 정리, 녹음 중 BPM 잠금과 취소를 검증합니다.
- 다음 우선순위는 실제 목소리·헤드폰·웹캠을 사용한 Phase 0 평가표와 Phase 2 박자 보정 확인입니다. 합성 입력의 상태·출력 검증만으로 실제 음질 또는 기기 지연 개선을 판단하지 않습니다.
- 합주 모드는 위 검증 이후 별도로 범위를 정합니다. 이번 안정화에는 WebRTC·방 서버·외부 API를 추가하지 않습니다.
