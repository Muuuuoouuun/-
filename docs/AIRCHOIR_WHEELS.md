# AirChoir 사용자 설정 휠 · 2026-10-04

## 구현 범위

AirChoir 안에서 **코드 악기 / 목소리 합창**, **한 손 / 두 손**, **손동작 / 클릭·키보드**를 구분합니다. band2sheet의 분석·악보 경로는 변경하지 않습니다.

- 코드 악기 한 손: 완성된 코드 하나를 선택합니다.
- 코드 악기 두 손: 첫 휠의 근음과 둘째 휠의 코드 종류를 조합합니다. 좁은 화면은 두 휠을 세로로 배치합니다.
- 목소리 합창: 기존 음정 검출·다이아토닉 화음 경로를 유지합니다. 한 손 지휘와 프리셋 클릭을 지원하며, 두 손 합창은 비활성화합니다.
- 설정: 완성 코드·근음·코드 종류·합창 프리셋 목록을 각각 추가·삭제·순서 변경하고 미리 봅니다. 취소는 초안을 버리고 적용만 저장합니다. 각 목록은 1~12개이며 중복·빈 목록·잘못된 값은 거부합니다. 카탈로그 자체의 항목 수가 적은 목록은 그 범위만 선택할 수 있습니다.
- 보관: localStorage에는 버전과 선택 목록·순서만 저장합니다. 카메라 영상·음성·참고 사진·장치 선택을 저장하지 않습니다. 오브 음원은 기존처럼 세션 메모리에만 있습니다. 저장 불가 시 현재 세션 적용과 저장 실패를 구분합니다.

## 오디오와 입력

코드 악기는 Web Audio의 삼각파 신스이며 외부 샘플·모델·API가 필요 없습니다. 같은 코드를 유지할 때 다시 발음하지 않고 공통 음을 이어 사용합니다. 화음 변경·종료 때 짧은 엔벌로프를 적용하고 종료된 노드를 정리합니다. 목소리용 기준 키는 자동 변경하지 않습니다.

녹음 버스는 선택한 제품 하나를 녹음합니다. 합창에서는 입력 음성과 화음, 코드 악기에서는 코드 신스입니다. 기존 루프와 메트로놈은 다시 녹음되지 않습니다. 코드 신스 녹음에는 마이크 왕복 지연 보정을 적용하지 않습니다. 제품 전환 시 진행 중 녹음을 취소하고 기존 오브를 정지 상태로 보존합니다. 동시 보컬+코드 녹음은 이번 범위가 아닙니다.

카메라 코드 입력은 기존 손 랜드마크의 손바닥 위치를 실제 휠 화면 좌표로 변환합니다. 선택된 손의 엄지·검지 핀치를 유지하며 같은 구역에서 150ms 머물러야 발음됩니다. 두 손은 양손 핀치와 근음·종류 쌍을 함께 확정합니다. 필수 손의 핀치 해제나 손 상실은 현재 코드와 후보를 즉시 지우고, 재입력은 새 150ms를 요구합니다. 기존 거리 히스테리시스를 재사용하며 핀치 해제의 시간 지연은 없습니다. 신스의 기존 80ms 발음 해제 엔벌로프는 유지합니다.

역할은 첫째·둘째 휠의 방향축과 이전 위치의 연속성으로 유지하며 인식 배열 순서나 손 크기로 바꾸지 않습니다. 휠 중앙 빈 영역·휠 밖도 선택되지 않지만 별도 OFF 조작을 요구하지 않습니다. 손동작 모드 중앙은 비버튼 안내이고 수동 입력의 OFF만 보존합니다. 추적이 모호하거나 교차하면 손을 내렸다 다시 올려야 합니다. 코드 관측이 250ms 넘게 없으면 선택과 발음을 해제하며, 300ms 콜백 감시는 합창에도 적용합니다. 종료·일시 중단된 카메라 트랙에서도 재발음하지 않습니다.

합창에서는 핀치가 기존 루프 녹음·잡기에 쓰이므로 손가락 수 제스처를 유지합니다. 카메라 손 상실·주먹 판정은 지연 없이 화음 선택을 지우고 재등장 때 이전 프리셋을 재사용하지 않습니다. 원음 모니터와 잔향의 오디오 경로는 변경하지 않습니다.

참고 사진 두 장은 시각 구성을 이해하는 데만 사용했습니다. 정지 사진만으로 원본 제품의 손 각도·벌림·오디오 매핑을 확인할 수 없으므로 동일한 동작을 복제했다고 주장하지 않습니다. 사진은 저장소에 포함하지 않습니다.

## 정지 동작

| 조작 | 현재 악기 | 기존 오브 | 메트로놈 |
|---|---|---|---|
| 코드 핀치 해제·필수 손 상실 / 수동 OFF·클릭 휠 벗어나기 | 발음 종료 | 재생 유지 | 유지 |
| 모든 소리 정지 / Esc / 창 초점 상실 / 화면 숨김 | 종료, 명시적 새 입력 대기 | 버퍼 보존·재생 정지 | 종료 |
| 제품·손 수·조작 변경 / 설정 열기·적용 | 종료, 새 선택 대기 | 버퍼 보존·재생 정지 | 종료 |
| 세션 종료 / 페이지 이탈 | 오디오·입력 자원 정리 | 삭제 | 종료 |

정지한 오브는 목록의 음소거 해제로 다시 재생합니다. 카메라 입력은 백그라운드에서 잠금을 풀거나 소리를 다시 켜지 않습니다. 창으로 돌아온 뒤 핀치를 풀었다 다시 맞대거나 손을 내렸다 올리는 새 입력이 필요합니다. 수동 OFF는 합창의 입력 모니터까지 끄는 동작이 아니므로 모든 출력을 멈추려면 모든 소리 정지를 사용합니다. 일반 핀치 해제·손 상실은 영상 녹화를 종료하거나 결과를 버리지 않습니다.

## 실행과 검증

최신 핀치 유지 입력의 검증 결과는 [VALIDATION.md](VALIDATION.md)에 있습니다. 아래 수치는 휠 기능을 처음 추가한 단계의 기록입니다.

`apps/airchoir`에서 `python3 -m http.server 8000 --bind 127.0.0.1`로 실행합니다. 코드 악기를 고른 뒤 **코드 악기로 시작**하면 장치 권한 없이 클릭·키보드로 연주할 수 있습니다. **카메라로 코드 연주**는 손동작으로 시작하며 카메라 실패 시 클릭 모드로 돌아갑니다. 카메라가 없는 실행 중 세션에서는 손동작 선택을 비활성화합니다.

```bash
cd apps/airchoir
npm test
npm run check
npm run check:performance
# 이미 설치된 Chrome을 쓰려면 BROWSER_CHANNEL=chrome
# 이미 설치된 Playwright를 쓰려면 PLAYWRIGHT_MODULE=/absolute/path/playwright/index.mjs
```

- 단위 검사 **115개 통과**: 코드·설정·신스·양손 선택·정지와 백그라운드 재개 차단, 기존 DSP·제스처·녹음 수명주기.
- 기존 실제 브라우저 검사 pointer·Phase 0·controls 통과. Escape 후 녹음 버튼 초점 복원 회귀도 수정·재검사했습니다.
- 새 실제 브라우저 검사 **18개 통과**: 설정 취소·적용·재진입·재로딩, 네 목록의 중복·빈 값, 한손→두손→합창, 합창의 기준 키 보존, 발음·OFF·전역 정지·녹음·모바일 설정을 다룹니다. 실제 Web Audio/AudioWorklet 출력과 녹음 버퍼를 측정합니다.
- 최대 12항목은 긴 코드명에서 버튼 겹침을 재현한 뒤 배치를 수정했습니다. 1440px·390px의 한/두 휠 모두 버튼 겹침 0, 최소 조작 크기 44px를 확인했습니다.
- 별도 로컬 합성 카메라 검사는 데스크톱 12개·모바일 12개 통과. Chrome fake video와 대체 랜드마크 결과를 실제 카메라 콜백·화면 좌표·신스에 연결해 손 유실·순서 변경·교차·프레임 중단을 확인했습니다. 실제 MediaPipe 모델 추론 검사가 아닙니다.

모든 검증은 기존 설치와 합성 입력으로 실행했습니다. 실제 카메라·마이크·모델 다운로드·유료 호출을 사용하지 않았습니다. 실제 목소리 음질·장치 지연·웹캠 인식률·Android 브라우저·모바일 Safari·장시간 세션은 미검증입니다. 390px 데스크톱 Chrome 에뮬레이션은 Android 실기기 검증을 대신하지 않습니다.

다음 단계는 짧은 실제 장치 사용성 평가입니다. 특히 두 손 위치 안내, 실제 시야각에서의 안정성, 코드 음색·음량과 녹음 박자를 확인한 뒤 기능 확장 범위를 정합니다.
