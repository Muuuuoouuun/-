# AirChoir 집중 연주와 영상 녹화

집중 연주는 기존 작업 화면의 카메라와 위젯을 크게 표시하는 화면입니다. 카메라 세션 준비가 끝나면 자동 진입하며, 준비된 수동 세션도 `집중 연주` 버튼으로 들어갈 수 있습니다. 수동 세션에서는 카메라가 없어 영상 녹화를 시작할 수 없습니다. 작업 화면과 집중 화면은 같은 악기·휠·세션을 사용합니다.

## 화면과 조작

집중 화면은 설정, 모든 소리 정지, 작업 화면 복귀, 영상 녹화, 전체 화면 조작을 유지합니다. 현재 악기·한 손/두 손 모드, 연주 입력 상태와 영상 녹화 상태를 따로 표시합니다. 손 입력이 끊겨도 녹화 표시와 시간이 계속 보입니다. 모바일에서는 도구 모음이 줄을 바꾸고 두 휠이 세로로 배치됩니다.

`작업 화면`은 세션을 종료하지 않습니다. 연주 소리를 정지하고, 진행 중인 영상을 마무리한 후 원래 화면으로 돌아갑니다. 기존 오브의 소리는 멈추지만 완성된 오브 버퍼는 남습니다. `전체 화면`은 명시적으로 누를 때만 브라우저 전체 화면을 요청합니다. 지원되지 않거나 거절되면 안내를 표시하고 일반 집중 화면을 유지합니다.

`Esc`는 집중 화면에서 작업 화면으로 복귀합니다. 설정창이 열려 있으면 설정만 취소하며 집중 화면은 유지합니다. 일반 작업 화면의 `Esc`는 기존 전체 소리 정지 정책을 따릅니다. 브라우저 전체 화면에서는 브라우저가 `Esc`를 먼저 소비할 수 있으므로 화면의 복귀 버튼도 항상 제공합니다.

## 녹화에 포함되는 것

`녹화 시작`을 누르면 준비된 카메라, 무대 위 현재 위젯, 앱의 전체 소리를 합칩니다. 별도 캔버스에 거울 방향의 카메라와 현재 코드/합창 위젯을 그립니다. 설정창·작업 패널·브라우저 전체 화면을 캡처하는 기능은 아닙니다.

소리는 기존 오디오 엔진의 최종 출력에서 가져오므로 현재 악기뿐 아니라 재생 중인 오브와 메트로놈도 포함합니다. 이미 준비된 오디오 트랙을 복제해 사용하며, 녹화를 위해 마이크를 다시 열지 않습니다. 녹화용 트랙 정리가 원래 세션의 카메라·오디오 트랙을 닫지 않도록 소유권을 구분합니다.

반복 재생용 **오브 오디오 녹음**은 별도 기능입니다. 오브는 선택한 악기 하나만 담고, 기존 루프·메트로놈은 제외합니다. 영상 녹화의 전체 출력과 혼동하지 않아야 합니다.

## 녹화 상태와 정지 규칙

녹화 버튼은 집중 화면에서 카메라가 준비되고 브라우저 기능이 지원될 때 활성화됩니다. 자동 진입이나 카메라 준비만으로 녹화하지 않습니다. 녹화 중에는 빨간 표시와 경과 시간을 유지합니다. 정지 요청 뒤에는 마지막 조각을 기다리는 `마무리 중` 상태로 바뀌며 새 녹화를 차단합니다.

| 조작·상태 | 연주 소리 | 영상 녹화·결과 |
|---|---|---|
| 중앙 OFF, 휠 벗어남, 손 인식 누락 | 현재 악기 선택 정지. 기존 루프 정책 유지 | 녹화 계속 |
| 모든 소리 정지 | 현재 악기·루프·메트로놈과 미리보기 정지 | 녹화 계속 |
| 영상 녹화 정지 | 별도 연주 정지 요청 없음 | 마무리 후 결과 유지 |
| 작업 화면 복귀·집중 화면의 `Esc` | 전체 소리 정지, 완성된 오브 버퍼 유지 | 마무리 후 작업 화면에 결과 유지 |
| 설정 열기/적용, 악기·손 수·입력 모드 변경 | 전체 정지 후 명시적 재선택 필요 | 진행 중 영상 마무리, 결과 유지 |
| 창 초점 이탈·페이지 숨김 | 전체 소리와 미리보기 정지 | 마무리 후 결과 유지 |
| 카메라 트랙 종료·입력 중단 | 카메라 입력 정리 정책 적용 | 마무리 후 결과 유지 |
| 세션 종료 | 장치·오디오 정리, 오브 버퍼 삭제 | 마무리 후 결과는 현재 페이지에 유지 |
| 새로고침·페이지 닫기 | 세션 종료 | 저장하지 않은 결과 소실 |

카메라 영상이 살아 있고 손 랜드마크만 사라진 상태는 카메라 종료와 다릅니다. 이때 악기는 기존 손 누락 정책으로 정지하지만 녹화는 계속됩니다. 영상 트랙이 끝났거나 영상 입력을 사용할 수 없으면 녹화를 마무리합니다. 트랙의 `muted` 상태가 1.5초 넘게 지속되는 경우도 입력 중단으로 처리합니다.

## 파일, 메모리와 제한

완성된 결과에는 실제 파일 형식·길이·크기, 재생 컨트롤, `영상 다운로드`, `영상 버리기`가 표시됩니다. 미리보기는 자동 재생하지 않으며 사용자가 재생하면 실시간 연주를 정지합니다. 다운로드도 사용자가 버튼을 눌러야 실행됩니다. 서버 업로드나 자동 파일 저장은 없습니다.

결과는 현재 페이지의 메모리와 로컬 Blob URL에만 있습니다. 작업 화면 복귀나 세션 종료 후에도 접근할 수 있지만 **새로고침하거나 페이지를 닫으면 사라집니다.** 녹화 중이거나 결과가 남아 있으면 페이지 이탈 경고를 요청하며, 브라우저가 경고를 표시하지 않거나 페이지가 강제로 종료되는 경우 복원할 수 없습니다. 저장할 영상은 먼저 다운로드해야 합니다.

한 번에 하나의 결과만 보관합니다. 다운로드가 끝나도 결과는 남고 새 녹화는 차단됩니다. `영상 버리기`를 누르면 미리보기를 멈추고 URL과 결과를 정리해 다음 녹화를 허용합니다. 저장하지 않고 버린 결과는 복구할 수 없습니다.

- **화면 크기:** 녹화 시작 시 무대 비율을 기준으로 긴 변 1280px, 총 921,600px 이내의 짝수 크기를 선택합니다. 이후 화면 크기가 바뀌어도 파일 크기는 고정하고 내용을 맞춰 그립니다.
- **프레임:** 캔버스 캡처에 30fps를 요청합니다. 실제 처리 속도와 파일 프레임 속도는 장치·브라우저에 따라 달라집니다.
- **형식:** 지원 여부를 VP9+Opus WebM, VP8+Opus WebM, WebM, MP4 순서로 확인합니다. 실제 MediaRecorder MIME을 파일 확장자와 표시 형식에 사용합니다. 지원 형식이 없으면 시작을 차단하고 이유를 표시합니다.
- **상한:** 최대 10분 또는 128MiB에 도달하면 정지합니다. 용량을 넘기는 조각은 더하지 않고 이미 받은 연속 구간을 보존합니다. 장시간·상한 크기의 실제 장치 녹화는 아직 검증하지 않았습니다.
- **비정상 종료:** 조각이 오랫동안 오지 않거나 마지막 종료 이벤트가 오지 않으면 제한 시간 후 오류를 알리고 확보된 조각을 정리합니다. 부분 결과는 정상 파일과 같은 완전성을 보장하지 않으므로 안내와 미리보기를 확인해야 합니다.

## 재현과 확인 범위

```bash
cd apps/airchoir
npm test
BROWSER_CHANNEL=chrome npm run check
BROWSER_CHANNEL=chrome npm run check:performance
BROWSER_CHANNEL=chrome SHOTS=/절대/결과/폴더 npm run check:focus
```

`check:focus`에는 기존 Playwright와 Chrome, `PATH`에 있는 `ffmpeg`·`ffprobe`가 필요합니다. 기존 Playwright를 별도 경로에서 사용할 때는 `PLAYWRIGHT_MODULE=/절대/경로/playwright/index.mjs`를 지정합니다. 검사 명령 자체는 브라우저·모델·의존성을 다운로드하지 않습니다.

집중 화면 회귀 검사는 **Chrome 가상 카메라·저장된 손 좌표·합성 소리**를 사용합니다. 모델 모듈은 로컬 fixture로 대체하고 외부 요청을 차단합니다. 실제 카메라·마이크를 열지 않습니다. 브라우저의 실제 MediaRecorder로 만든 결과를 명시적으로 다운로드하고 `ffprobe`로 스트림을 읽고 `ffmpeg`로 화면과 음성을 디코딩합니다.

2026-10-04 확인에서는 집중 화면 회귀 항목이 모두 통과했습니다. 생성된 WebM은 VP9 영상과 Opus 오디오, 1222×752px, 1.899초, 189,227바이트였습니다. 카메라와 위젯의 인코딩된 픽셀, 유효한 오디오 신호, 미리보기 정지, 손 인식 누락 중 녹화 지속, 화면/설정/모드/초점/카메라/세션 경계에서 결과 보존을 확인했습니다. 외부 네트워크 요청과 페이지 오류는 없었으며, 가상 장치 요청은 영상만 사용했습니다. 단위 검사와 기존 포인터·Phase 0·컨트롤·퍼포먼스 회귀도 통과했습니다.

1440×1000 데스크톱과 390×844 모바일 폭에서 실제 앱 화면을 확인했습니다. 별도 UI 배치 검사에서는 844×390 가로 화면과 최대 12항목의 두 휠도 확인했으며, 도구 버튼 최소 44px·겹침 없음·가로 넘침 없음을 확인했습니다. 저장소 밖 QA 자료는 `qa/airchoir-focus-implementation/focus-results.json`, 녹화 파일과 디코딩 프레임, 데스크톱·모바일 스크린샷에 있습니다. 실행 결과의 전체 범위는 [VALIDATION.md](VALIDATION.md)를 참고하세요.

실제 카메라·손 인식 모델 정확도, 실제 목소리 음질과 마이크 동기화, 장시간 녹화, Android 성능·음질, 모바일 Safari 및 MP4 파일 생성은 미검증입니다. 합성 입력의 기능 회귀 통과는 모델·오디오 품질이나 실제 장치 프레임 속도 개선의 증거가 아닙니다.
