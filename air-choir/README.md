# AirChoir

> 허밍 한 번이면, 내가 합창단.

마이크에 노래하면 내 목소리로 화음이 쌓이고, 카메라 앞에서 손을 움직여 합창단을 지휘하는 브라우저 앱입니다.
기획은 [PLAN.md](PLAN.md), 화음 엔진 비교는 [phase0/](phase0/README.md)에 있습니다.

지금은 **Phase 2(오브 모드)**까지 구현되어 있습니다. 합창단 모드와 오브 모드는 한 화면에서 같이 동작합니다.

## 실행하기

카메라와 마이크를 쓰려면 내 컴퓨터에서 실행합니다. (`localhost`는 카메라·마이크 권한이 허용됩니다)

```bash
cd air-choir
python3 -m http.server 8000
# Chrome에서 http://localhost:8000 열기
```

설치할 패키지는 없습니다. 손 인식(MediaPipe)은 처음 시작할 때 인터넷에서 받아 옵니다 (약 20MB, 이후 브라우저 캐시).

시작 화면의 버튼 세 개:

| 버튼 | 소리 | 손 |
|---|---|---|
| 카메라·마이크로 시작 | 내 목소리 (이어폰 필수) | 카메라 |
| 데모 노래로 시작 | 합성 목소리 "작은 별" | 카메라 |
| 카메라 없이 마우스로 해 보기 | 데모 노래 | 마우스 위치 + 키보드 `0`~`5`, 버튼 누르기 = 핀치 |

## 손동작

| 손동작 | 효과 |
|---|---|
| 손이 안 보임 | 화음 없음 (내 목소리만) |
| 손가락 1개 | 3도 위 |
| 손가락 2개 | 3도 + 5도 위 |
| 손가락 3개 | 3·5도 + 옥타브 아래 베이스 |
| 손가락 4~5개 | 풀 합창 (4성부) |
| 주먹 (엄지만 펴도 마찬가지) | 즉시 정지 |
| 손 높이 | 합창단 음량 |
| 손 좌우 | 왼쪽: 어둡고 울림 많게 / 오른쪽: 밝고 선명하게 |

- 손이 둘 보이면 카메라에 더 가까운(크게 보이는) 손을 씁니다.
- 손가락 개수는 같은 값이 0.09초 이상 이어져야 바뀌고, 손이 0.25초 안에 다시 보이면 화음이 끊기지 않습니다.
- 화음은 고른 키의 스케일 안에서 계산되어 불협화음이 나지 않습니다.
- 화음 엔진은 기본 PSOLA이고, `Q` `W` `E`로 그레인 / PSOLA / 합성을 바꿀 수 있습니다. Phase 0 평가 결과가 나오면 기본값을 정합니다.

## 오브 (반복 녹음)

소리를 눈에 보이는 구슬로 만들어 쌓는 루프 스테이션입니다.

| 손동작 | 효과 |
|---|---|
| 핀치(엄지+검지) 유지 | 다음 마디부터 녹음 (기다리는 동안 남은 박을 셈). 놓으면 그 마디 끝에서 완성, 최대 4마디 |
| 완성된 오브를 들고 휙 | 날아가서 멈춘 자리에서 반복 재생. 좌우 위치 = 소리 방향, 위쪽일수록 크게 |
| 들고만 있다가 핀치 · 손 내리기 | 그 자리에 내려놓기 (4초 지나면 자동) |
| 오브를 핀치 | 잡아서 옮기기 |
| 오브 위에서 주먹 | 터뜨려서 지우기 |
| 오브 위에 편 손 1초 | 음소거 켜고 끄기 |

- 오브는 최대 6개. 색은 녹음한 음의 높이(낮으면 파랑, 높으면 주황·분홍), 크기는 길이입니다.
- 녹음에는 **내 목소리와 화음**만 들어갑니다. 이미 돌고 있는 오브와 메트로놈은 빠져서 겹쳐 녹음되지 않아요.
- 모든 오브는 박자 그리드에 맞춰, 녹음했던 순간의 위치를 이어서 재생됩니다.
- 마이크로 부를 때는 메트로놈을 듣고 부르는 지연(출력 + 입력)만큼 뒤에서 잘라 와서 박을 맞춥니다.
- 메트로놈은 녹음을 기다리거나 녹음하는 동안 자동으로 켜집니다. 빠르기는 70~130 BPM이고, 오브가 있는 동안은 바꿀 수 없어요.
- 핀치 중에는 손가락 개수(화음 구성)를 바꾸지 않습니다. 주먹은 핀치와 구분합니다. 주먹도 엄지·검지 끝이 가깝지만 검지가 손바닥 쪽으로 말려 있어요.

## 구조

| 경로 | 내용 |
|---|---|
| `index.html` | 앱 화면과 스타일 |
| `src/app.js` | 시작 흐름, 입력 전환, HUD, 음정 그래프 |
| `src/gestures.js` | 손 랜드마크 → 손가락 개수·주먹·높이·좌우 (순수 로직) |
| `src/hands.js` | 카메라 + MediaPipe HandLandmarker |
| `src/audio.js` | 오디오 그래프 (하모나이저 → 밝기 필터 → 합창단 음량 → 리버브), 녹음 버스, 오브 재생, 메트로놈 |
| `src/stage.js` | 카메라 위 그리기: 손 뼈대, 링, 화음 오브, 루프 오브, 게이지 |
| `src/orbs.js` | 박자 그리드와 오브 상태 (녹음 → 들기 → 던지기 → 재생, 옮기기, 터뜨리기, 음소거) (순수 로직) |
| `core/recorder.js`, `core/recorder-worklet.js` | 최근 40초를 계속 담아 두고 요청한 마디 구간만 잘라 주는 녹음기 |
| `core/dsp.js` | 음정 검출, 화음 계산, 화음 엔진 3종 (Phase 0에서 검증) |
| `core/worklet.js` | 오디오 스레드에서 하모나이저 실행 |
| `phase0/` | 화음 엔진 비교 테스트 벤치 |

내 목소리(모니터)는 오디오 처리를 거치지 않고 바로 나가서 추가 지연이 없습니다.

## 테스트

```bash
cd air-choir
npm test        # 단위 테스트 26개: 오디오 처리·녹음기 8 + 손동작·핀치 10 + 오브 8 (Node 22)
npm run check   # 헤드리스 Chromium으로 앱과 Phase 0 화면을 끝까지 실행 (playwright 필요)
```

- 손동작 판정은 MediaPipe 공식 샘플 사진 9장(주먹, 손가락 1개, V, 엄지척, 편 손 등)에서 뽑은 **실제 랜드마크**(`test/fixtures/hands.json`)로 검증합니다. 사진 속 손 11개가 모두 맞게 판정됩니다.
- `app.check.mjs`는 가짜 카메라에 손 사진을 순서대로 비추고(1개 → V → 편 손 → 주먹), 화면이 손동작과 화음을 따라가는지 확인합니다. 오브는 마우스 모드에서 녹음 → 던지기 → 옮기기 → 음소거 → 터뜨리기까지 실제 오디오로 확인합니다(녹음된 오브에 소리가 들어 있는지까지). 처음 실행할 때 MediaPipe 패키지와 사진을 `test/.cache`에 받습니다.
- 주소 끝에 `#cpu`를 붙이면 GPU 대신 CPU로 손을 인식합니다 (GPU 가속이 없는 환경용).

## 아직 확인하지 못한 것

- 실제 웹캠과 실제 목소리로 함께 쓸 때의 체감 (자동 테스트는 사진과 합성 목소리로만 확인)
- 손 사진이 없는 3개·4개 손가락과 핀치는 실제 편 손 랜드마크를 변형해서 검증 (카메라로 핀치하는 장면은 자동 테스트하지 못함)
- 마이크 녹음의 박자 보정이 실제 기기에서 맞는지
- 모바일 Safari
